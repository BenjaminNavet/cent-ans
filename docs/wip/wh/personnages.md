# WH — personnages (seigneurs, héros, traits, suite) vs TWW3

Lecture seule du code au 2026-10-09. Références `core/crates/sim-campaign/src/` (abrégé `sc/`), `data/`, `game/scripts/`.

## 1. Résumé

- Déjà proche de TWW3 : XP et points de compétence (`sc/skills.rs:33-50`), arbre de 30 compétences en 3 branches x 3 paliers (`data/skills/`), 59 traits dont 12 acquis, suite de compagnons = ancillaries (`sc/retinue.rs`, `data/retinue.json`), agents espion/héraut/prédicateur avec 11 actions et niveaux (`data/rules/agents.json`), rançon/parole/captifs beaucoup plus riches que TWW3 (`sc/ransom.rs`), ordres de chevalerie (`sc/chivalry.rs`), traditions d'armée (`sc/traditions.rs`), loyauté des vassaux au niveau faction (`sc/feudal.rs`), fiche personnage et portraits (`character_sheet.gd`, `data/portraits/archetypes.json`).
- Manque le plus : (1) la progression ne produit aucun jalon visible ni déblocage (pas de niveau, un seul arbre pour tous, effets minces) ; (2) les blessures sont permanentes et sans soin ; (3) la loyauté individuelle d'un personnage est un champ mort ; (4) aucun héros ne peut agir sur un personnage (assassinat, embuscade, aide à une armée) ; (5) pas de mécanique propre par faction (légitimité, actes royaux à recharge) ; (6) on ne peut pas recruter de capitaine ; (7) l'XP ne vient que de bataille et de gouvernement.

## 3. Top 10 (impact / coût)

**1. Actes royaux à recharge (équivalent des rites) — #12, #13.**
- `data/royal_acts/*.json` + `data/schemas/royal_act.schema.json` : id, nom FR, `cost` (prestige et/ou livres), `cooldown_turns`, `requires` (faction, titre, trait), `effects` (vocabulaire `EffectKind` existant, durée en saisons), `sources`.
- Nouveau module `sc/royal_acts.rs` : `RoyalActsState { last_used: BTreeMap<ActWithFaction, u32> }` dans `CampaignState`, ordre `Order::RoyalAct { act }`, validation (prestige suffisant via `change_ruler_prestige`, recharge), application des effets comme `edicts.rs`.
- Exemples historiques : Sacre à Reims (France, prestige + piété), Chevauchée royale (Angleterre : moral + butin), Lit de justice, Joyeuse Entrée (Bourgogne, ordre public), Cour plénière, Trêve de Dieu.
- Bridge `godot-bridge` : `get_royal_acts` / `do_royal_act`, UI : bouton dans `court_panel.gd`. IA : `ai/src/campaign/` choisit l'acte le plus rentable quand il est disponible.
- Tests : recharge respectée, prestige débité, sauvegarde/chargement, IA ne dépasse pas le prestige.

**2. Blessures temporaires — #1, #17.** Ajouter `expires_in_turns` au trait (schéma + `data-model`), `traits_expiry` dans `CharacterState` (serde default), purge dans `resolve_characters`. Durée de base 4 saisons divisée par `1 + WoundRecovery/100`. Test : un général blessé guérit après N tours, le trait opposé reste exclusif.

**3. Recrutement de capitaines — #6.** `Order::HireCaptain { settlement }` dans `orders/order.rs` et `orders/mod.rs` ; génération déterministe (`state.rng` ou rng dérivé) d'un `CharacterState` (nom tiré de `data/names`, maison de la faction, command 1-3) ; coût indexé sur le niveau de prix (monnaie H5) ; plafond = 2 + prestige/50. IA : étendre `assign_generals` (`ai/src/campaign/characters.rs:38-75`). Tests : coût débité, armée sans général reçoit un capitaine, refus si trésor insuffisant.

**4. Loyauté des personnages vivante — #5, #19.** Lire `CharacterState.loyalty` : baisse saisonnière si le personnage est vassal-gouverneur d'une province en révolte, rançon refusée par son chef, titre accordé à un rival ; en dessous de 25, événement « défection » (le général emmène l'armée chez un voisin ennemi, ou le gouverneur rend la province aux rebelles) ; au-dessus de 75, bonus de moral. Module `sc/loyalty.rs`, constantes `data/rules/dynasty.json`. Tests : défection déterministe, un ordre de chevalerie (`member_loyalty`) protège.

**5. Assassinat / empoisonnement — #8.** Dans `data/rules/agents.json` ajouter actions `assassinate` et `poison` (hostile, `death_risk` 60, `reveals`, condition `at_war` ou `hostile_character_present`) ; nouveau `ActionEffect::Wound` et `ActionEffect::Kill` dans `data-model` et `agents/effects.rs` ; cible = gouverneur ou général présent dans la colonie (jamais le souverain avant niveau 4 de l'agent). Conséquence diplomatique : attitude -20 chez tous. Test : déterminisme, la mort passe par `characters::kill` donc la succession est résolue.

**6. XP élargie et annonces de niveau — #2, #7.** Constantes dans `data/rules/dynasty.json` (siege_xp, raid_xp, treaty_xp, ransom_xp), appel à `grant_experience` depuis `dynasty::on_siege_won`, `on_raid_led`, `negotiation/apply.rs`, `ransom.rs`. `EventKind::LevelUp` + toast dans `season_report.gd`. Test : un siège gagné donne l'XP, le seuil franchi donne un point.

**7. Déclencheurs de traits en données — #14, #15.** `data/trait_triggers.json` : liste `{trait, when: {counter, min}|{age_min}|{event}}`, schéma, évaluation dans `dynasty` en fin de tour (remplace les 4 blocs codés `dynasty.rs:341-406`). Ajouter 6 traits : héros de bataille, pieux, endetté, vieux, chasseur de rançons, pillard.

**8. Compétences par rôle — #3.** `requires_role` dans `skill.schema.json` ; `learnable_skills` filtre sur le rôle du personnage (souverain, général, gouverneur, épouse) ; ajouter 12 compétences de spécialité. Test : un gouverneur ne voit pas les compétences de commandement de rang 3.

**9. Faits d'armes sur la fiche — #18.** Exposer `battles_fought`, `sieges_won`, `raids_led`, `captive_count` dans `get_character` (bridge) et afficher dans `character_sheet.gd`. Pas de nouvelle règle. Test : smoke UI.

**10. Aide à l'armée et embuscade par agent — #9.** Actions `guide_army`/`ambush` dans `agents.json`, effets sur `movement` (+1 pas, ou retard) lus depuis `AgentsState` ; test de mouvement avec agent adjacent.

## 4. Refontes lourdes (L)

**A. Mécanique propre par faction (légitimité).** Un trait de jeu par grand bloc : France = légitimité du sacre (monte avec Reims, victoires, justice ; baisse avec défaites, traité de Troyes) conditionnant la loyauté des vassaux ; Angleterre = ban et chevauchée (prestige de guerre convertible en solde) ; Bourgogne = alliances et mécénat ; Papauté = faveur existante ; factions orientales = autre ressource. Données `data/faction_mechanics/*.json` + `sc/faction_mechanic.rs` + jauge dans le HUD. Dépend des actes royaux (#12) et de la loyauté (#5).

**B. Arbres de compétences par archétype (souverain, connétable, intendant, évêque) de 40-60 compétences.** Reprend #3/#4 à l'échelle TWW3 ; nécessite un éditeur de données, des icônes (déjà un pipeline `tools/`), un équilibrage ; à ne lancer qu'après #8.

**C. Héros comme personnages (agents liés à `CharacterState`).** Un agent devient un personnage (portrait, traits, XP propre, mort/capture) ; remplace `agents/` actuel (état léger) ; impact : sauvegarde, IA, UI de carte (`agent_controller.gd`). À considérer seulement si #5 et #10 montrent le besoin.
