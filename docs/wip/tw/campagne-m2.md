# TW — critique campagne vs Medieval II (rôle `campagne-m2`)

Domaine : boucle de campagne (agents, religion, papauté, dynastie, missions, victoire, ravitaillement, commerce). Code lu : `core/crates/sim-campaign/src`, `ai/src`, `data/`. Ne reprend pas WH/WR/RX/UX5/CO. Aucune modification hors ce rapport.

## 1. Résumé

Déjà proche de M2 : agents à sceau 1-5 avec 15 actions (espion, héraut, prédicateur), papauté (faveur, excommunication, Grand Schisme, médiation, don), hérésies qui se propagent, ordres de chevalerie, mercenaires par région, réserves de recrutement qui se régénèrent, suite de généraux, loyauté vivante, attrition et ravitaillement, routes commerciales, brouillard de guerre. Les ordres militaires (Teutoniques, Hospitaliers, Calatrava) existent comme factions.

Ce qui manque le plus : (a) la religion d'une province ne change jamais (seule une hérésie s'y superpose) ; (b) la papauté ne dirige rien (ni croisade papale, ni interdit, ni conseil) ; (c) la dynastie est subie (le joueur ne choisit pas son héritier, un mariage ne donne ni dot ni prétention) ; (d) les missions du conseil sont 14 modèles territoriaux et seules 4 factions ont des objectifs de victoire propres ; (e) ni marchand ni guilde.

## 3. Top 10 (impact / coût)

1. **DesignateHeir (#4, S).** Fichiers : `orders/order.rs` (variante), `orders/mod.rs` (validation), `characters.rs` (lire `Faction.heir` en priorité, déjà fait), `godot-bridge` (ordre), `game/scripts/ui/family_tree_view.gd` (bouton). Règles : vivant, même faction, pas le souverain ; si loi dynastique et non légitime : -prestige (`dynasty.json`). Tests : `designate_heir_*` (refus hors maison, succession effective, guerre de succession via `contested_succession`). Rapport de coût faible, impact fort.
2. **Retinue à 40 compagnons (#9, S).** `data/retinue.json` seul ; chaque compagnon : déclencheur existant, effets via `EffectKind` connus. Test : le test de schéma `data/schemas` et un test de portée (`retinue.rs`) tirent au moins un nouveau compagnon.
3. **Plus de variété de missions (#6, S).** Ajouter les compteurs `AgentActions`, `Marriages`, `Ransoms` dans `data-model/src/entities/missions.rs`, branchés dans `agents/effects.rs`, `dynasty.rs:169`, `ransom.rs`. 15 modèles dans `data/missions.json` avec récompenses existantes. Tests : un compteur par but.
4. **Excommunication élargie + interdit (#3, S).** `religion.rs` : fonction `excommunication_triggers` appelée depuis `diplomacy/war.rs` (rupture de trêve), `capture.rs` (exécution d'un captif chrétien). État `interdict_until` dans `FactionState`, malus d'ordre via `population.rs`. Levée par `donate_to_church`/`request_papal_mediation`. Tests : déclenchement, durée, levée.
5. **Prétention dynastique par mariage (#5, M).** `dynasty.rs::resolve_births` : à la naissance, si les parents sont de deux factions, `Claim { kind: Throne, faction: Some(autre), expires_turn: None }` portée par la faction du père si l'enfant est héritier. Texte : « enfant de ... ». Tests : après naissance, `casus_belli` non nul ; l'IA (`diplomacy/ai.rs:46`) pèse la prétention.
6. **Conversion de province (#1, M).** Voir tableau. Étapes : `ProvinceState.faith_override`, `conversion_progress` (sauvegarde `serde(default)`), `religion::resolve_conversion` après `resolve_heresy` (`religion.rs:358`), lecture dans `population.rs:362` et dans le pont (`campaign_sim_diplomacy.rs:200`). Données `data/rules/religion.json`. Tests : province étrangère convertie en N saisons, plus vite avec prédicateur (`Preach` ajoute au progrès), jamais pour le propriétaire de même foi.
7. **Croisade papale (#2, M).** `religion::resolve_papal_crusade` (nouvelle phase appelée avec `resolve_religion`). Cible : province tenue par une autre foi dans `holy_land` (réutilise `crusade.json`) ou provinces d'un excommunié. Récompenses : faveur +15, prestige +10 au premier preneur, `Crusade` événement. IA : `ai/src/campaign/economy.rs` ajoute un biais d'attaque vers la cible. Tests : l'appel ne se déclenche qu'une fois par fenêtre, la récompense va au premier preneur.
8. **Marchand (#7, M).** `AgentKind::Merchant` + 3 actions dans `data/rules/agents.json` (`actions` est piloté par données, `agents/mod.rs:45 rules`), effets dans `agents/effects.rs`, lecture dans `trade.rs::resolve_route`. IA dans `agents/ai.rs`. Tests : bonus de route, rival réduit, plafond d'agents.
9. **Désertion sur solde impayée (#11, S).** `economy.rs:721` : compteur `unpaid_seasons` dans `FactionState`, seuil dans `economy.json`. Tests : 2 saisons négatives, perte de X %, événement ; trésor positif remet le compteur à 0.
10. **Objectifs de victoire étendus (#8, M).** `ObjectiveCondition::{Prestige, Treasury, HoldTitle}` dans `faction.rs:100`, lecture dans `victory.rs:70-125`. Écrire les objectifs de 8 factions jouables. Tests : un cas par condition.

## 4. Refontes lourdes (L)

- **Brouillard IA (#13).** Faire lire `VisionMask` à l'IA (`ai/src/campaign.rs`) : décisions limitées à ce que la faction voit. Gros risque d'équilibrage (IA moins bonne) ; faire d'abord une option `ai_fog` de difficulté (`data/rules/difficulty.json`), mesurer avec les sondes d'IA (`docs/wip/ia-nuit.md`).
- **Pape comme entité (cardinaux, conseil, élection).** Un personnage-pape avec trait, mort et élection, des États pontificaux jouables. Dépend d'un travail de données (histoire des papes 1337-1453). À ne faire qu'après #2 et #3.

## 5. Constats sans écart

- Recrutement par colonie avec réserve régénérante : fait (`recruit_pool.rs`, ADR 0102) ; mercenaires par région : fait (`mercenaries.rs`, ADR 0103).
- Loyauté, défection des généraux, désertion avec armée : fait (`loyalty.rs`, WH charsb).
- Ordres de chevalerie : fait (`chivalry.rs`) ; ordres militaires : factions jouables.
- Arbre généalogique : fait (`family_tree_view.gd`).
- Attrition hivernale et ravitaillement : fait (`economy.rs:961-994`).
- Ports et commerce maritime : routes et blocus (`trade.rs`, `sea_lanes.rs`) ; marins d'agent : absents (voir #7).
