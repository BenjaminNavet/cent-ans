# TW — transitions campagne ↔ bataille et enrobage de partie

Rôle `transitions`. Références : Medieval II (M2), Total War: Warhammer III (WH3). Lecture seule du code ; rien lancé.

## 1. Résumé

- Déjà proche de TW : écran d'avant-bataille complet (rapport de forces par le cœur, pertes estimées, renforts alliés, météo/site prévus, embuscade, Combattre / Résolution automatique / Retraite ou Maintenir le siège) ; écran de fin riche (verdict nuancé, pertes par régiment, héros, captifs, XP, étendards, rejeu) ; classes de victoire du cœur (`battle_outcome.rs`) ; débandade/retraite de campagne (`movement/retreat.rs:179`) ; autosave avant bataille ; bataille personnalisée, 3 batailles historiques, tutoriel de 14 étapes ; choix de faction avec objectifs historiques.
- Manque le plus : (1) la **résolution automatique n'a aucun écran de résultat** (journal seulement) ; (2) les **captifs ne se règlent pas à chaud** (rançon/libération/exécution seulement plus tard au panneau de rançons) ; (3) **pas de poursuite** du vaincu ni de retraite du défenseur ; (4) l'issue historique des batailles historiques n'est jamais comparée ; (5) chargement à durée minimale fixe de 3 s.
- Cité « déjà » pour éviter les doublons : WH uicards top3/top5 (captifs, pertes estimées), WR captives (exécution, ADR 0303), EP9 (bataille refusée), EP13 (rejeu), CV3 (classes d'issue), A6-L1 (barre = probabilité).

## 3. Top 10 (impact / coût)

1. **Écran de résultat de résolution automatique (#1).** `godot-bridge` : `auto_resolve_battle` renvoie `{events, result:{winner, attacker/defender:{losses, general_captured, general_killed}}}` ; avant l'appel, `BattleAftermath.snapshot`, après, `diff`. `battle_result_screen.gd` : nouveau `show_auto_summary(title, player_side, result, aftermath)` sans tableaux de régiments (réutiliser `banner_title`, `verdict`, cartes Captifs/XP/Butin). `campaign_map._on_battle_auto` l'affiche avant `_offer_pending_battles`. Tests : `game/tests` fichier `auto_resolve_summary_test.gd` (dictionnaire fixe → lignes attendues) ; test Rust sur le dict du pont.
2. **Captifs tranchés dans l'écran de fin (#2).** Carte « Captifs et rançons » : pour chaque `aftermath.captives[i]`, trois boutons Rançonner/Libérer/Exécuter (confirmation en deux temps comme `ransom_panel.gd`) ; appel direct des ordres existants dès le retour (`_on_battle_returned`, file de décisions) ; le chiffre « rançon à percevoir » (`:497`) devient réel. Test : `wr_captives_ui_test.gd` étendu.
3. **Risque lisible sur « Résolution automatique » (#6).** Ajouter à `BattleForecast` `general_loss_pct` (calculé avec `capture_chance_percent`) et l'afficher en pastille sur `auto_button` (`pre_battle_dialog.gd:200-207`) + tooltip `battle_auto_resolve`. Test Rust : prévision sans toucher le RNG de campagne (invariant du module).
4. **Chargement skippable (#7).** `battle_loading_card.gd` : `close()` ne dort plus si `Settings` `skip_loading` ou si clic ; garder 3 s pour la première bataille de la partie. Test : card_test existant.
5. **Comparaison historique (#8).** Dans `battle_scene` (hors campagne, `historical != {}`), passer `historical_winner`, `summary` à `show_result` (nouvel argument facultatif) → carte « Dans l'Histoire » ; textes dans `data/ui/`. Test : résultat Crécy côté Français gagnant → « Vous avez renversé l'Histoire ».
6. **Retraite générale propre (#10).** `BattleEnd::Withdrawal` dans `decision.rs`, émis quand `withdraw_all` est confirmé et que le camp du joueur est encore constitué ; `resolve_pending_battle` : pas de déroute, pertes limitées, moral −10 comme `WITHDRAW_MORALE_LOSS`. Tests dans `battle_request` et `decision`.
7. **Carte de site dans l'avant-bataille (#5).** `Control` `SiteSketch` dessiné d'après `_preview.get_*` (relief, rivière, bois, routes) ; une seule texture 256 px ; zéro règle. Test : `smoke` + dimension.
8. **Retraite du défenseur hors siège (#4).** `battle_forecast.rs` : `can_withdraw` vrai pour le défenseur si pas d'embuscade ni de siège ; `withdraw_pending_battle` : retrait → `retreat_beaten_army` avec `losses_percent` 0 et −10 moral ; l'attaquant gagne la province. Tests : cas défenseur, cas embuscade (refusé).
9. **Briefing de début de campagne (#11).** Fenêtre unique au tour 1 (avant le tutoriel) lisant `get_victory_objectives` ; case « ne plus afficher ».
10. **Compositions nommées de bataille personnalisée (#13).** `custom_battle_screen.gd` : clé `custom_battle/presets` (dict nom → config) ; liste déroulante + « Enregistrer ».

## 4. Refontes lourdes

- **Poursuite en campagne (#3, M-L)** : un tour « poursuite » où le vainqueur peut forcer un deuxième engagement sur l'ost en déroute (M2/WH3 la rendent via l'auto-résolution ou la bataille « Poursuite »). Nécessite points de mouvement restants, règle de rattrapage par cavalerie, et un nouveau type de `BattleRequest` (`pursuit: true`, pas de retraite possible).
- **Renforts de voisinage (#14)** : armées amies à ≤ N jours de marche rejoignent la bataille (WH3 « renforts ») avec arrivée différée dans `sim/reinforcements.rs` ; demande des règles de coalition, d'ordre d'entrée et de tests de déterminisme.
- **Écran de fin de campagne complet (#12)** : frise historique, comparaison avec l'Histoire (1337-1453), scores par faction, possibilité de « continuer en bac à sable ».
- À ne pas refaire (déjà) : prévision/retraite/embuscade (A6-L1, EP9), rejeu EP13, captifs (WR captives), pertes estimées (WH uicards top5).

Note : #9 non vérifié en détail (lecture rapide) ; à confirmer avant de coder.
