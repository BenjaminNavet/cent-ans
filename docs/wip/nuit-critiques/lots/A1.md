# Lot A1 — robustesse des sauvegardes

État : implémenté, tests en cours de validation (voir le commit).

Fait :
- `core/crates/game-api/src/saves.rs` : `write_atomic` (tmp + sync + rename) pour le wrapper et la fiche meta ;
  `parse_wrapper` refuse un `version` plus récent (message FR) et applique `WRAPPER_MIGRATIONS` (vide) ;
  erreurs de lecture en français (« sauvegarde abîmée ou illisible ») ; `file_stem` jamais vide
  (`sans_nom`), `.`/`..`, noms réservés Windows, point/espace final, longueur bornée, contrôles retirés ;
  `stem_is_lossy` ; `delete_save` supprime aussi `<stem>.played`.
- Fixture `core/crates/game-api/tests/fixtures/save_v9.json` (Angleterre, graine 1337, 10 tours) et
  `tests/save_fixture.rs` (charge, joue un tour, re-sauve). Règle : toute hausse de `STATE_VERSION`
  ou `SAVE_VERSION` ajoute un fixture.
- Client : l'échec d'autosave de fin de tour affiche un toast et renseigne `TurnFlow::last_autosave_error`.

Points ouverts :
- `a:b` et `a/b` donnent toujours le même fichier (compat. des saves existantes) ; la boîte de dialogue
  du client peut utiliser `stem_is_lossy` / comparer `file_stem` pour armer la confirmation.
- Autosave « avant la bataille » (`flow/battles.rs`) : échec toujours seulement dans le dump, pas de toast.
- `write_sidecar` du client (`.played`) n'est pas atomique.
